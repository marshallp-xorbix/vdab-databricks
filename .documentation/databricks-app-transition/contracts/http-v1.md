# VDAB HTTP contract v1

**Status:** Implemented subset is listed below; broader builder, workspace, AI, and deployment routes remain planned for Steps 5–7. Unity Catalog table discovery, the Unity Catalog Delta EditableDataWindow contract, BarChart, LineChart, PieChart, DonutChart, AmoebaStory, FlowFieldStory, HeatMapStory, HoneycombStory, NetworkWebStory, PulseWaveStory, SpiralStory, TerrainStory, and DashboardEmbed are implemented locally; Apps scopes and generated SQL/Streamlit behavior remain unverified in a Databricks workspace.  
**Date:** 2026-10-20.  
**Scope:** Standalone Databricks App installations only. This API never accepts SaaS tokens, tenant IDs, workspace-connection IDs, or browser-supplied Databricks hosts.

Versioned routes are same-origin under `/api/v1` (the liveness path is `/api/health/live`). JSON request and response bodies use UTF-8 and camelCase. IDs are opaque strings. Error responses use `application/problem+json` with stable `code`, `title`, `detail`, and `requestId` fields. A `401` means the Databricks app session/token is missing or invalid; `403` means the caller lacks project access, OAuth scope/consent, or the underlying Databricks permission. A denied user operation is never retried under the VDAB app identity.

## Projects, components, workflows, and portability

| Method and path | Purpose | Authorization and result |
| --- | --- | --- |
| `GET /api/v1/projects` | List only projects created by or shared with the caller. | App identity for Lakebase access; project ACL enforced for caller; `200 {items: ProjectSummary[]}` |
| `POST /api/v1/projects` | Create a project with metadata and an empty/default canvas. | Caller becomes creator; `201 Project` |
| `GET /api/v1/projects/{projectId}` | Read the current project metadata summary. Aggregate sections are exposed by their versioned project subresources as those slices are implemented. | Creator/collaborator; `404` for unrelated users |
| `PUT /api/v1/projects/{projectId}` | Save editable project metadata and, as the aggregate slices are completed, components, workflow, custom modules, resource references, and child-app link using optimistic `version`. | `DELETE /api/v1/projects/{projectId}` | Delete an install-local project after client confirmation. | Creator or installation recovery admin; audited |
| `GET /api/v1/projects/{projectId}/components` | Read the ordered component collection and current project version. Stable component keys, component types/versions, code names, descriptions, properties, bindings, children, and layout are returned. | Creator/editor or audited installation recovery admin; `404` for unrelated users |
| `PUT /api/v1/projects/{projectId}/components` | Atomically replace `{version, components}`. | `GET /api/v1/component-definitions` | Return the versioned 33-component catalog, default properties, supported events/bindings, and four installed-workspace binding schemas. | Signed-in app user |
| `GET /api/v1/component-definitions/{type}` | Return one component definition; unknown types return a sanitized `404`. | Signed-in app user |
| `POST /api/v1/projects/{projectId}/preview` | Generate deterministic child-app source from the latest saved project version. Request body is empty; response is `{projectId, version, previewOnly: true, files: [{path, content}]}`. | Creator/editor or audited installation recovery admin; `404` for unrelated users; `409` if project metadata and component snapshots changed between reads; `422` for invalid supported-control properties or unsupported component types |
| `GET /api/v1/projects/{projectId}/export` | Read a consistent ACL-scoped aggregate snapshot and export standalone schema v1. Workspace resource IDs/hosts and child-App identity are omitted; resource display labels and usage locations are retained for reselection. | Creator/collaborator or audited installation recovery admin; `200 StandaloneProjectExport`; `404` for unrelated users |
| `POST /api/v1/projects/import` | Validate a standalone v1 bundle (maximum 1 MiB; custom module source maximum 256 KB), reject SaaS/authority/secret fields, and atomically create a caller-owned project, aggregates, unresolved resource references, and audit event. Resource and child-App selection are required again. | Caller becomes creator; `201 ImportResult`; `409` on duplicate project name; invalid bundle is `400` |
| `GET /api/v1/projects/{projectId}/collaborators` | List project-specific access grants. | Creator or recovery admin |
| `PUT /api/v1/projects/{projectId}/collaborators` | Grant an explicit Databricks user ID project editor access. | Creator or audited recovery admin; never changes Databricks workspace permissions |
| `DELETE /api/v1/projects/{projectId}/collaborators/{userId}` | Revoke one project editor grant; repeated removal is idempotent. | Creator or audited recovery admin; `404` for an unavailable project; never changes Databricks workspace permissions |
| `GET /api/v1/projects/{projectId}/audit` | Read creator/collaborator/deployment events for the project. | Creator/collaborator; installation admin recovery path is audited |

The project aggregate preserves component order and stable keys. Workflow action kinds are `triggerToast`, `showModal`, `saveToTable`, `buildSql`, `runSql`, `setBinding`, `startDatabricksJob`, `callCustomModule`, and `callPrebuiltModule`. Workspace-owned resources are referred to by project-local `resourceKey`; imported projects require the user to resolve these keys again in the current workspace.

Standalone export/import preserves portable project metadata, theme, ordered component and workflow definitions, and custom Python module source. Current-workspace resource identities are replaced by unresolved labels with component/workflow usage references; ModelChat endpoint IDs, Genie space IDs, dashboard origins, Lakebase/Unity Catalog table coordinates, SQL warehouse IDs, Jobs IDs, and child-App identity are not carried across installations. Import validates the whole nested document before writing and commits the project, components, workflows, custom modules, unresolved references, and audit event in one Lakebase transaction. Imports begin with the importing Databricks user as owner. JSON import is capped at 1 MiB and custom module source at 256 KB. This implementation is covered by local contract/service/HTTP tests and local PostgreSQL rollback tests only; it has not been exercised in a Databricks workspace.

The metadata update request permits only `name`, nullable `description`, and positive integer `version`; workspace hosts, workspace IDs, credentials, SaaS fields, and unknown properties are rejected. A stale version produces a sanitized RFC 9457 problem response. Installation-admin project enumeration and recovery reads/mutations append audit events; project list recovery uses one aggregate event with the visible project count.

The component replacement request requires a positive integer project `version` and an ordered `components` array. Each component has a stable `key`, one of the 33 retained `type` values, positive `schemaVersion`, optional positive `componentVersion`, JSON object `properties`, optional `bindings`, ordered `children`, and optional `layout`. Component order is the array order. Child membership is checked for missing keys, duplicate parents, self-reference, and cycles. The API rejects workspace/connection IDs, workspace hosts, SaaS tenant/account IDs, tokens, secrets, credentials, and unknown top-level component fields. Dropdown properties require a non-empty label and list of `{value: string}` options, correctly typed optional settings, and a valid multiselect default. DatePicker properties require a non-empty label, valid ISO date values/bounds, supported date format, and ordered bounds. TimePicker properties require a non-empty label, `now` or valid ISO time values, and a whole-number step from 1 through 82,800 seconds. Slider properties require a non-empty label, finite precise numeric values, ordered bounds, in-bound scalar/range values, positive step within the range, valid ranged mode, and a supported Streamlit numeric format. Label properties accept only `text: string`, `fontSize: small|medium|large`, and `bold: boolean`; HTML text is escaped in the generated runtime. Component replacement, project version/timestamp update, and audit append commit in one transaction.

The component-definition routes are stateless. Their defaults and binding schemas contain no workspace host or credential authority. Resource selectors use only the installed workspace; importing a project into another installation requires resource reselection. Registry metadata is an editor contract, not proof that every component is editable, generated, or runnable yet. The current standalone editor supports TextInput properties (label, placeholder, default value, help, disabled, type, multiline, and height), Button properties (label, primary/secondary variant, disabled, and help), Checkbox properties (label, default checked, help, and disabled), Toggle properties (label, default value, help, and disabled), Dropdown properties (label, string options, default option, placeholder, help, disabled, and single/multiselect mode), DatePicker properties (label, default date, minimum/maximum date, display format, help, and disabled), TimePicker properties (label, default time, step in seconds, help, and disabled), Slider properties (label, min/max, scalar default or range endpoints, step, display format, help, disabled, and scalar/ranged mode), Label properties (text, small/medium/large font size, and bold), Expander properties (section title, expanded by default, and ordered first-level control children), Columns properties (1–12 positional slots with ordered control children), Rows properties (1–12 ordered vertical slots with first-level control children), Tabs properties (one or more labels, a default pane, and multiple first-level controls per pane ordered by `layout.tabIndex` and `layout.y`), Form properties (submit label, clear-on-submit, Enter-to-submit, border, width, height, and ordered direct control children excluding Button), Modal properties (title, supported dialog width, position, dismissal behavior, and ordered direct controls or layout containers), and DataWindow properties (label, optional maximum rows, width, height, index visibility, placeholder, scrolling flag, and a current-workspace Unity Catalog table selection). Modal's deprecated nullable integer width/height values remain accepted for saved legacy definitions; integer dimensions do not map to a current dialog size or height setting. Removing a populated tab confirms before removing its controls and shifting later pane indexes. Other component records remain preserved and are reported as unsupported by preview until their editor and generator slices are complete.

EditableDataWindow exposes all agreed display settings, fixed/dynamic row mode, disabled state, and a selected table key column. Save/import validates metadata and the preview editor retains primary-key edit restrictions. The full generated-source and error behavior is described below.

The current preview generator accepts empty projects, the nine supported controls, Expanders containing ordered first-level controls, Columns containing ordered positional controls, Rows containing ordered vertical controls, Tabs with controls assigned to ordered panes, Forms with ordered supported direct controls and one submit button, Modals containing supported controls or first-level layout containers, DataWindow and EditableDataWindow bound to Unity Catalog tables. DataWindow source uses the viewer's forwarded token with the installed workspace's configured SQL warehouse, quotes resource identifiers, optionally applies `maxRows`, and renders `st.dataframe` options plus column labels; an incomplete binding emits a schema-only DataFrame. EditableDataWindow enables writes only for Delta format. Its generated source uses a viewer-token named SQL parameter for the JSON change set and one atomic `MERGE`; it checks that the selected key is non-null and unique across the full table before non-empty saves. Other table formats remain read-only. The key preflight and MERGE are separate statements, so concurrent writes can invalidate the preflight. Direct table discovery, SQL scopes/permissions, DML, and generated runtime behavior inside a Databricks App remain unverified. Both DataWindow Lakebase runtime bindings remain pending. It emits `app.py` with the project title, label overrides, session-state defaults, supported Streamlit control calls, escaped-HTML `st.markdown` output for Label, `with st.expander(...)`, `st.columns(count)`, Rows `st.container()`, Tabs `st.tabs(...)`, `with st.form(...)` with configured flags/dimensions and one `st.form_submit_button`, and named `@st.dialog(...)` functions with a close action. Modal direct children are ordered by `layout.y` then aggregate order, and their layout metadata is removed before rendering the control; nested layout children keep their own child order. Rows use `pass` when empty and `st.text('Row N')` for unfilled trailing slots; empty tab panes show their tab label; empty forms and dialogs display placeholders. Streamlit evaluates all tab panes on each rerun by default. Button `onClick`, control `onChange`, Form `onSubmit`, and Modal invocation through the workflow `ShowModal` action are not wired until the workflow slice is implemented. Generated source is displayed in VDAB and is not executed, deployed, or treated as a runnable child app. Unsupported components and malformed supported properties fail explicitly; the generator never silently drops persisted components.

FileUpload is now part of the locally implemented component contract. Its properties contain an optional `label`; its optional binding shape is `{databricksVolume:{bindingType:"databricksVolume",source:{kind:"resource",valueType:"file",resource:{type:"databricksVolume",catalog,schema,volume,filePath}}}}`. Catalog/schema/Volume fields may be incomplete while editing but preview requires all three names. `filePath` is an empty or safe relative folder; absolute paths, separators inside resource names, traversal segments, extra authority fields, and unknown nested fields are rejected both on save/import and during generation. The editor supports multiple-file selection; generated Volume uploads use raw bytes and the current viewer token, with no app-identity retry. The Python preview remains source-only. Local tests do not prove Databricks Apps OAuth scope compatibility or real Volume permissions.

The Genie spaces route returns `{items:[{spaceId,title}],authenticationMode}`. A successful empty `items` list means the caller can use the discovery route but no Genie spaces are visible; a missing scope, consent, or resource grant returns a sanitized Problem Details response. The selected space is persisted as a stable ID and display title only; workspace hosts and tokens are never accepted in component properties.

The serving-endpoint route returns `{items:[{name,readiness,permissionLevel}],authenticationMode}`. An authorized empty list means no endpoints are visible; 401/403/upstream failures remain distinct sanitized Problem Details responses. The endpoint name is the only persisted selection. Node discovery calls the installed workspace's documented serving-endpoint list API using the acting user's forwarded token and a bounded response. Generated ModelChat source invokes `/serving-endpoints/{name}/invocations` with the child viewer's forwarded token; it never grants query access to the VDAB service principal. `permissionLevel` is informative discovery metadata, while every inference request remains subject to the acting viewer's endpoint permission.

Discovery endpoints distinguish a successful empty result from missing OAuth consent or workspace grants. Query values may select resources within the installed workspace; there is no `workspaceUrl`, connection ID, host header override, or refresh token in their contracts.

| Method and path | Purpose | Authorization |
| --- | --- | --- |

The server rejects a browser-supplied workspace host. Create/link/deploy failures, missing scope/consent, quota, name collision, resource access denial, and upload/deploy failures produce explicit errors and audit outcomes without service-principal fallback. Existing app overwrite requires confirmation and a recorded recoverable previous source/deployment. The current Apps authorization page documents Jobs as a user-authorization use case but does not list a `jobs` scope in its supported scopes; generated-app Jobs execution and builder Jobs operations remain unproven until the spike finds and exercises the exact supported API/SDK scope and permission path.

## Lakebase Autoscaling discovery routes

| Method and path | Purpose | Authorization and limits |
| --- | --- | --- |
| `GET /api/v1/workspace/lakebase/projects` | List Lakebase Autoscaling projects visible in the installed workspace. | Forwarded caller token with the `postgres` scope; local mock is marked and is not workspace evidence. |
| `GET /api/v1/workspace/lakebase/branches?projectId={id}` | List branches for one project. | Caller token; resource IDs only, no host or connection authority. |
| `GET /api/v1/workspace/lakebase/endpoints?projectId={id}&branchId={id}` | List branch endpoints. | Caller token; SaveToTable requires a read-write endpoint. |
| `GET /api/v1/workspace/lakebase/databases?projectId={id}&branchId={id}` | List branch databases. | Caller token. |
| `GET /api/v1/workspace/lakebase/schemas?projectId={id}&branchId={id}&endpointId={id}&databaseName={name}` | List PostgreSQL schemas visible to the caller. | Caller token plus a 300-second user OAuth database credential; the user's email must have a PostgreSQL role. |
| `GET /api/v1/workspace/lakebase/tables?projectId={id}&branchId={id}&endpointId={id}&databaseName={name}&schemaName={name}` | List base tables, views, and visible column metadata. | Same caller identity and metadata permissions; visibility does not imply insert permission. |

All calls use the trusted installed-workspace host. IDs and values are validated and bounded; schema/table SQL is parameterized and limited. The credential is not returned or logged. Local route, client, and adapter tests do not prove deployed App scope, PostgreSQL role, endpoint connectivity, or write permission.


## Workflow SQL warehouse reference

A standalone `buildSql` action may save a paired `sqlWarehouseId` and `sqlWarehouseName` selected from `GET /api/v1/workspace/resources/sql-warehouses`. The ID is workspace-local, contains no workspace host or credential, and is accepted only for `unityCatalogTable`. The generated `runSql` action passes that ID to the SQL Statement API helper, which uses the viewer's forwarded token and runtime `DATABRICKS_HOST`; a missing selection falls back only to the existing child-App `DATABRICKS_SQL_WAREHOUSE_ID` resource binding and fails explicitly if neither is configured. It never falls back to the VDAB service principal. The API boundary validates the paired fields and rejects malformed IDs, a warehouse on a Lakebase source, and authority fields. The standalone export/import flow must require warehouse reselection across installations. This is local contract and source-generation evidence only; workspace scopes, warehouse grants, and child-App binding/deploy behavior are not verified.
