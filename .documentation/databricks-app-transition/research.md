# Databricks platform research

## Official-source recheck — 2026-10-21

This read-only check used current official Databricks documentation. No workspace, CLI, OAuth, Lakebase, child App, or Marketplace request was made.

- The [Databricks Apps Lakebase resource guide](https://docs.databricks.com/aws/en/dev-tools/databricks-apps/lakebase) says Autoscaling uses the `postgres` resource key, Provisioned uses `database`, both inject the same PostgreSQL environment variables, and an app resource creates/grants a database role for the app service principal. Adding Autoscaling requires `CAN MANAGE` on the Lakebase project. The same guide says existing Provisioned databases can still be bound but new Provisioned databases cannot be created after March 12, 2026; new apps should use Autoscaling. These resource grants do not create or grant a role for each end user.
- The [Generate OAuth credentials API](https://docs.databricks.com/api/postgres/v1/generate-database-credential) requires the `postgres` API scope and an endpoint name in the Autoscaling form `projects/{project_id}/branches/{branch_id}/endpoints/{endpoint_id}`. Credential TTL must be between 300 and 3600 seconds. This matches the generated Autoscaling runtime's resource path/credential request shape, but does not prove the child App can obtain viewer-scoped credentials or that each viewer has a PostgreSQL role and table grants.
- The [Lakebase role guide](https://docs.databricks.com/aws/en/oltp/projects/manage-roles) says OAuth roles are linked to a Databricks identity and branch role state is independent. The [connection quickstart](https://docs.databricks.com/aws/en/oltp/projects/connect-overview) says other Databricks identities need OAuth Postgres roles created before they can authenticate. The generated runtime therefore connects as the forwarded viewer identity and requires a separately granted viewer role; it must not switch to the child App role after denial.
- The [Databricks Apps dependency guide](https://docs.databricks.com/aws/en/dev-tools/databricks-apps/dependencies) says pip-based Apps use Python 3.11 and install packages from `requirements.txt`; `uv` Apps can choose their Python version. PyPI lists `asyncpg==0.32.0` as supporting Python 3.9+, including CPython 3.11 Linux wheels. The local verification environment on this machine is Python 3.14.3, so the PostgreSQL integration proves generated SQL behavior but not a Python 3.11 package install.
- The [Apps deployment guide](https://docs.databricks.com/aws/en/dev-tools/databricks-apps/deploy) detects `package.json` at the deployment root, installs dependencies, runs the build script when present, and starts the configured app command. This supports the repository's packaged Node artifact shape; it does not prove a VDAB deployment.
- The [App Spaces guide](https://docs.databricks.com/aws/en/dev-tools/databricks-apps/app-spaces) documents `CAN CREATE APP` as a permission that may be granted within an App Space. G2 must record whether the target workspace uses App Spaces and test that permission alongside forwarded-token app scopes, create/link/deploy, resource binding, and denied-user behavior.
- The [Marketplace provider guide](https://docs.databricks.com/aws/en/marketplace/get-started-provider) documents provider enrollment and profile/listing prerequisites. It does not establish VDAB's eligibility, App-specific package submission, security review, commercial path, or update process; G4 still needs direct Databricks partner guidance.

These sources describe platform contracts only. The generated Lakebase Autoscaling code was executed against disposable local PostgreSQL 17, not Databricks. G2, G3, G4, OAuth scope/consent, role grants, fresh-install durability, child-App lifecycle, and Marketplace operations remain unverified.

## Genie Chat workspace authorization and API — checked 2026-10-20

The official [Genie Space API reference](https://docs.databricks.com/api/genie/v1/genie-space) lists spaces at `GET /api/2.0/genie/spaces`; `page_size` is capped at 100, and each record includes a `space_id` UUID and title. The official [Genie conversation API reference](https://docs.databricks.com/api/genie/v1/genie-start-conversation) documents `POST /spaces/{space_id}/start-conversation` with the first message's `content`, follow-up `POST /conversations/{conversation_id}/messages`, `GET /conversations/{conversation_id}/messages/{message_id}`, and the attachment query-result endpoint. The start/follow-up response contains a message ID, conversation ID and asynchronous message state. The query-result endpoint is available while a message is executing a query or after it completes; it returns a SQL Statement Execution response with a manifest and first result chunk. Pagination links are opaque workspace paths, so generated output does not follow them or display temporary external links.

These Genie APIs require the `genie` scope. Databricks' [Apps authorization guide](https://docs.databricks.com/aws/en/dev-tools/databricks-apps/auth) documents the same user scope and the forwarded `x-forwarded-access-token` header, including the Streamlit `st.context.headers.get(...)` access shape. The [Genie conversation guide](https://docs.databricks.com/aws/en/genie-agents/conversation-api) recommends polling every 1–5 seconds with exponential backoff, limiting most waits to ten minutes, and starting one conversation per app session. Its cancel endpoint is for Agent mode; Chat mode has no documented cancel operation. The generated child app therefore bounds each wait, lets users check again manually, handles a returned `CANCELLED` status, and does not claim it can cancel an in-flight Chat-mode response. Every operation uses the acting viewer's forwarded token and never falls back to the app service principal after denial. Tokens, prompts, raw API bodies and temporary result links are not logged or shown.

The official versioned [Streamlit 1.38 `st.chat_input` reference](https://docs.streamlit.io/1.38.0/develop/api-reference/chat/st.chat_input) documents inline inputs inside layout containers and multiple chatbot inputs; its [container](https://docs.streamlit.io/1.38.0/develop/api-reference/layout/st.container) and [chat message](https://docs.streamlit.io/1.38.0/develop/api-reference/chat/st.chat_message) references document the bounded message area and chat roles used by the generated source. Current Streamlit docs are not evidence of the exact customer runtime.

This is current-documentation evidence only. No Genie API, workspace resource listing, OAuth consent, child-app runtime, or permission behavior was exercised.

## Tabs legacy contract inspection — 2026-10-19

The legacy Tabs registry defaults to `{tabs: ["Tab 1", "Tab 2"], defaultTabIndex: 0}`. Its save validator requires at least one non-empty tab name, trims names for the 100-character check, and requires `defaultTabIndex` to refer to a configured tab when present. A Tabs component's ordered `children` IDs identify all pane children; each child carries layout `{tabIndex, y}`. The editor groups by tab index and sorts by y. The generator emits a tab container per label and a text placeholder with the tab label for empty panes. The editor can add/rename tabs and asks before removing a tab that contains components; removal deletes its child subtrees and reindexes children assigned to subsequent panes. The standalone aggregate already has `properties`, ordered `children`, and JSON `layout`, so no route or migration is expected.
