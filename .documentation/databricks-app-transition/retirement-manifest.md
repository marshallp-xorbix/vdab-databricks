## Per-batch procedure

1. Mark source files and transitive consumers in the parity matrix; record the replacement tests and a Databricks development-workspace result.
2. Remove one group at a time and update its docs, route config, tests, package manifests/lockfiles, scripts, and CI in the same change.
3. Search the whole tracked repository for the retired API/type/environment names, run import/link scans, typecheck, tests, build, and packaged Databricks smoke tests.
4. Record any intentional historical mention in an archived requirements/research document; the active setup and architecture docs must describe only the standalone product.
