# VDAB HTTP contract v1

**Scope:** Standalone Databricks App installations only. This API never accepts SaaS tokens, tenant IDs, workspace-connection IDs, or browser-supplied Databricks hosts.

Versioned routes are same-origin under `/api/v1` (the liveness path is `/api/health/live`). JSON request and response bodies use UTF-8 and camelCase. IDs are opaque strings. Error responses use `application/problem+json` with stable `code`, `title`, `detail`, and `requestId` fields. A `401` means the Databricks app session/token is missing or invalid; `403` means the caller lacks project access, OAuth scope/consent, or the underlying Databricks permission. A denied user operation is never retried under the VDAB app identity.

The project aggregate preserves component order and stable keys. Workflow action kinds are `triggerToast`, `showModal`, `saveToTable`, `buildSql`, `runSql`, `setBinding`, `startDatabricksJob`, `callCustomModule`, and `callPrebuiltModule`. Workspace-owned resources are referred to by project-local `resourceKey`; imported projects require the user to resolve these keys again in the current workspace.

Standalone export/import preserves portable project metadata, theme, ordered component and workflow definitions, and custom Python module source. Current-workspace resource identities are replaced by unresolved labels with component/workflow usage references; ModelChat endpoint IDs, Genie space IDs, dashboard origins, Lakebase/Unity Catalog table coordinates, SQL warehouse IDs, Jobs IDs, and child-App identity are not carried across installations. Import validates the whole nested document before writing and commits the project, components, workflows, custom modules, unresolved references, and audit event in one Lakebase transaction. Imports begin with the importing Databricks user as owner. JSON import is capped at 1 MiB and custom module source at 256 KB. This implementation is covered by local contract/service/HTTP tests and local PostgreSQL rollback tests only; it has not been exercised in a Databricks workspace.

The metadata update request permits only `name`, nullable `description`, and positive integer `version`; workspace hosts, workspace IDs, credentials, SaaS fields, and unknown properties are rejected. A stale version produces a sanitized RFC 9457 problem response. Installation-admin project enumeration and recovery reads/mutations append audit events; project list recovery uses one aggregate event with the visible project count.

The component replacement request requires a positive integer project `version` and an ordered `components` array. Each component has a stable `key`, one of the 33 retained `type` values, positive `schemaVersion`, optional positive `componentVersion`, JSON object `properties`, optional `bindings`, ordered `children`, and optional `layout`. Component order is the array order. Child membership is checked for missing keys, duplicate parents, self-reference, and cycles. The API rejects workspace/connection IDs, workspace hosts, SaaS tenant/account IDs, tokens, secrets, credentials, and unknown top-level component fields. Dropdown properties require a non-empty label and list of `{value: string}` options, correctly typed optional settings, and a valid multiselect default. DatePicker properties require a non-empty label, valid ISO date values/bounds, supported date format, and ordered bounds. TimePicker properties require a non-empty label, `now` or valid ISO time values, and a whole-number step from 1 through 82,800 seconds. Slider properties require a non-empty label, finite precise numeric values, ordered bounds, in-bound scalar/range values, positive step within the range, valid ranged mode, and a supported Streamlit numeric format. Label properties accept only `text: string`, `fontSize: small|medium|large`, and `bold: boolean`; HTML text is escaped in the generated runtime. Component replacement, project version/timestamp update, and audit append commit in one transaction.

The component-definition routes are stateless. Their catalog metadata and defaults contain no workspace authority. The 33 definitions are available to the editor and validated during project save, import, and source generation. Invalid component types and malformed properties fail explicitly instead of being silently omitted.

EditableDataWindow exposes all agreed display settings, fixed/dynamic row mode, disabled state, and a selected table key column. Save/import validates metadata and the preview editor retains primary-key edit restrictions. The full generated-source and error behavior is described below.

The current preview generator accepts empty projects and retained component and workflow-action types with implemented schemas and focused contract coverage, including controls, charts, story visualizations, layout containers, data windows, file upload, dashboard/Genie/Model integrations, and workflow actions. DataWindow and EditableDataWindow can bind to Unity Catalog or Lakebase tables. DataWindow source uses the viewer's forwarded token with the installed workspace's configured SQL warehouse, quotes resource identifiers, optionally applies `maxRows`, and renders `st.dataframe` options plus column labels; an incomplete binding emits a schema-only DataFrame. EditableDataWindow enables writes for Delta tables and Lakebase Autoscaling/Provisioned tables. Its generated source uses a viewer-token named SQL parameter for the JSON change set and one atomic `MERGE`; it checks that the selected key is non-null and unique across the full table before non-empty saves. Other table formats remain read-only. The key preflight and MERGE are separate statements, so concurrent writes can invalidate the preflight. Direct table discovery, SQL scopes/permissions, DML, and generated runtime behavior inside a Databricks App remain unverified. Generated Lakebase runtime bindings support Autoscaling and existing Provisioned resources; Provisioned behavior has local fake-runtime evidence only. It emits `app.py` with the project title, label overrides, session-state defaults, supported Streamlit control calls, escaped-HTML `st.markdown` output for Label, `with st.expander(...)`, `st.columns(count)`, Rows `st.container()`, Tabs `st.tabs(...)`, `with st.form(...)` with configured flags/dimensions and one `st.form_submit_button`, and named `@st.dialog(...)` functions with a close action. Modal direct children are ordered by `layout.y` then aggregate order, and their layout metadata is removed before rendering the control; nested layout children keep their own child order. Rows use `pass` when empty and `st.text('Row N')` for unfilled trailing slots; empty tab panes show their tab label; empty forms and dialogs display placeholders. Streamlit evaluates all tab panes on each rerun by default. Button `onClick`, control `onChange`, Form `onSubmit`, and Modal invocation through the workflow `ShowModal` action dispatch through the generated workflow runtime. The preview response is explicitly marked preview-only and source is not executed by the builder. Child-App deployment is a separate implemented lifecycle described below; live upload and generated runtime behavior remain unverified. Unsupported components and malformed supported properties fail explicitly; the generator never silently drops persisted components.

FileUpload is now part of the locally implemented component contract. Its properties contain an optional `label`; its optional binding shape is `{databricksVolume:{bindingType:"databricksVolume",source:{kind:"resource",valueType:"file",resource:{type:"databricksVolume",catalog,schema,volume,filePath}}}}`. Catalog/schema/Volume fields may be incomplete while editing but preview requires all three names. `filePath` is an empty or safe relative folder; absolute paths, separators inside resource names, traversal segments, extra authority fields, and unknown nested fields are rejected both on save/import and during generation. The editor supports multiple-file selection; generated Volume uploads use raw bytes and the current viewer token, with no app-identity retry. The preview route returns source only; deployment uses a separate lifecycle. Local tests do not prove Databricks Apps OAuth scope compatibility, real Volume permissions, or generated child-App execution.

The Genie spaces route returns `{items:[{spaceId,title}],authenticationMode}`. A successful empty `items` list means the caller can use the discovery route but no Genie spaces are visible; a missing scope, consent, or resource grant returns a sanitized Problem Details response. The selected space is persisted as a stable ID and display title only; workspace hosts and tokens are never accepted in component properties.

The serving-endpoint route returns `{items:[{name,readiness,permissionLevel}],authenticationMode}`. An authorized empty list means no endpoints are visible; 401/403/upstream failures remain distinct sanitized Problem Details responses. The endpoint name is the only persisted selection. Node discovery calls the installed workspace's documented serving-endpoint list API using the acting user's forwarded token and a bounded response. Generated ModelChat source invokes `/serving-endpoints/{name}/invocations` with the child viewer's forwarded token; it never grants query access to the VDAB service principal. `permissionLevel` is informative discovery metadata, while every inference request remains subject to the acting viewer's endpoint permission.

Discovery endpoints distinguish a successful empty result from missing OAuth consent or workspace grants. Query values may select resources within the installed workspace; there is no `workspaceUrl`, connection ID, host header override, or refresh token in their contracts.

The deploy request contains no App Space or workspace identifier. The server reads the installed VDAB App name from trusted `DATABRICKS_APP_NAME`, fetches that App with the acting user's forwarded token, and derives the target App Space from its response. Create-new sends that same space when one is reported; link-existing and recovery require a matching space. An explicit `null` or empty `space` value maps to an unspaced App. If the Databricks response omits `space`, VDAB rejects the response and blocks deployment before any child-App mutation; it does not infer that the builder is unspaced. The public target response uses `null` for an explicit unspaced result or when the effective-scope field is omitted. For a space-bound target, deployment fails closed if effective user scopes are unavailable. The published Apps REST schema omits the `space` field, while the first-party CLI and SDK expose it; the exact response and create behavior therefore still require manual confirmation in an installed workspace.

Secret selections contain only an App resource key, secret scope, and secret key. Create-new grants fixed `READ`; permission applies to the entire scope, so administrators should use a dedicated scope containing only the required secrets. The generated `app.yaml` maps `VDAB_SECRET_<APP_RESOURCE_KEY>` to that resource with `valueFrom`. Linked targets expose only resource identifiers and permissions; each existing read-only secret must be selected to match the target's exact supported resource set. Secret values are never sent to VDAB, stored in Lakebase, returned by the target route, or written to generated source. See [Databricks secret resources](https://docs.databricks.com/aws/en/dev-tools/databricks-apps/secrets) and [resource environment variables](https://docs.databricks.com/aws/en/dev-tools/databricks-apps/environment-variables); live injection and workspace grants remain manual tests.

## BarChart preview contract — locally implemented, workspace unverified

BarChart properties contain `title`, `seriesColor`, `xAxis`, and `yAxis`. Axis objects contain `field`, `displayName`, `scaleType`, and `transform`. The binding is an installed-workspace `unityCatalogTable` with selected column metadata; incomplete configuration is preserved while editing and produces an explanatory source preview. Save/import and preview reject unknown properties, unsafe/missing axis fields, unsupported aggregations, and incompatible column types. Generated source quotes Unity Catalog identifiers, uses only allowlisted SQL expressions, applies a 10,000-row ceiling, and renders a native Streamlit Vega-Lite bar specification. Lakebase binding records remain preserved but unsupported by this chart runtime. This contract does not prove Databricks OAuth scope compatibility, SQL permissions, or a running child app.

## LineChart preview contract — locally implemented, workspace unverified

LineChart properties use the same `title`, `seriesColor`, `xAxis`, and `yAxis` shape and installed-workspace Unity Catalog table binding. Save/import and preview validate the chart type, axis metadata, selected table columns, and allowed Y transforms. X bucketing is not supported for LineChart. With Y transform `none`, the generated query returns raw rows ordered by X; aggregate transforms group by X. Output uses an allowlisted, identifier-quoted SQL query, the viewer's forwarded token, and a 10,000-row cap. The Streamlit output uses a Vega-Lite line mark with point overlays and filters invalid/blank rows. Incomplete configuration remains editable with an explanatory preview; Lakebase bindings are preserved with an unsupported-runtime message. The output is preview-only, and the contract does not prove OAuth scope compatibility, SQL grants, or a running child app.

## PieChart preview contract — locally implemented, workspace unverified

PieChart properties use `title`, `seriesColor`, `category`, and `value` plus an installed-workspace Unity Catalog table binding. Category supports passthrough only; value supports raw numeric rows or type-checked allowlisted aggregates. Save/import and preview validate the property shape, selected metadata, and compatible value type. Preview SQL uses quoted identifiers, the viewer's forwarded token, and a 10,000-row cap. ## Workflow SQL warehouse reference

A standalone `buildSql` action may save a paired `sqlWarehouseId` and `sqlWarehouseName` selected from `GET /api/v1/workspace/resources/sql-warehouses`. The ID is workspace-local, contains no workspace host or credential, and is accepted only for `unityCatalogTable`. The generated `runSql` action passes that ID to the SQL Statement API helper, which uses the viewer's forwarded token and runtime `DATABRICKS_HOST`; a missing selection falls back only to the existing child-App `DATABRICKS_SQL_WAREHOUSE_ID` resource binding and fails explicitly if neither is configured. It never falls back to the VDAB service principal. The API boundary validates the paired fields and rejects malformed IDs, a warehouse on a Lakebase source, and authority fields. The standalone export/import flow must require warehouse reselection across installations. This is local contract and source-generation evidence only; workspace scopes, warehouse grants, and child-App binding/deploy behavior are not verified.
